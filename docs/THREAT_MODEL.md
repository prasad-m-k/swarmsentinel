# SwarmSentinel threat model

What SwarmSentinel defends against, how, with what evidence, and where it stops. Agent-action controls live in the gateway (`asp_gateway.py`) or Sentinel (`sentinel.py`), configured from ASP policy files. HTTP identity and session isolation are enforced independently at the API boundary (`auth.py`, `server.py`).

## System model

- **Agents** are LLM-driven and untrusted. Their reasoning can be steered by anything in their context window, so their own narration is never evidence.
- **The ASP gateway** sits between agents and tools. It sees every in-band call (tool use, spawn, message) before execution and decides from policy, identity and lineage, never from the model's reasoning. This follows the ASP preprint's Algorithm 1.
- **The Sentinel** watches executed interactions as a weighted directed graph and raises tripwires on swarm-level patterns. With feedback enabled, a tripwire revokes the implicated agents and their descendants.
- **Content sources** carry trust levels from the policy (`content-trust`): system prompt high, user input medium, tool responses low, retrieved documents untrusted.

## Adversaries and failure modes

1. **Indirect prompt injection**: adversarial instructions inside content an agent retrieves (a document, web page or tool output).
2. **A compromised or misaligned agent** that tries to exceed its delegated authority or recruit other agents.
3. **Emergent swarm failure** with no adversary at all: recursive delegation, feedback loops between agents, write storms on shared state.

## Coverage

Status key: **Enforced** means calls are blocked before execution. The four real-agent sandbox tools use engine-owned evaluation and dispatch (`POST /api/swarm/sessions/{id}/execute`); generic SDK wrappers and scripted synthetic scenarios remain cooperative. **Report-only** means real AI Village records are scored counterfactually; those actions had already happened. **Gap** means not covered.

## Known gaps

- **G1. Generic interception remains cooperative; remote sandbox execution is not.** `evaluate` and `agent.call` still only authorize caller-side actions. Bypassing those wrappers is not stopped. The real-agent runner instead calls `execute`, which derives enforcement metadata and evaluates/dispatches four registered tools inside the engine under one lock. Skipping the SDK cannot bypass ASP through that API. Unknown tools, argument/metadata forgery, revoked or out-of-scope actors, invalid lineage, contamination and foreign sessions cannot dispatch these bodies. The owner-only one-time initializer fixes fixture mode/trust and never accepts paths. Untrusted reads taint the actor and descendants, not just an invented span. This does not mediate arbitrary host access or other external tools. Previous latency numbers for the cooperative `evaluate` path (Apple M2: p50 0.024 ms local / 0.39 ms localhost HTTP) are not measurements of the new execution path.
- **G2. Taint propagation is off for AI Village.** Village agents share broadcast chat rooms, so propagating through messages would mark nearly every agent as tainted within minutes and carry no signal. Real deployments with directed agent-to-agent channels are the intended setting.
- **G3. Loop and budget controls are coarse.** The `delegation_loop` tripwire follows hand-off chains through messages and assumes an agent's next message continues the chain it last received; it can miss loops that pass through shared state, and it may flag legitimate iterative review. A 3-agent loop also trips `rapid_consensus` on the same event. The step budget counts actions, not tokens or cost, and there is no global budget across a swarm. Both are off for AI Village, where broadcast chat makes hand-off chains ambiguous.
- **G4. Contamination is assigned, not detected.** The adapter labels reads as untrusted by source (web fetches, retrieved files). SwarmSentinel does not inspect content for injection text; it limits what a context can do once it has read untrusted content, which is the ASP paper's approach.
- **G5. Taint travels only through messages.** Writing to shared state (a repository, a wiki) and having another agent read it back is not yet a propagation path.
- **G6. Not an operating-system or tamper-proof boundary.** Remote sandbox bodies are owned by the engine and are only exposed through its evaluated dispatch API; the runner no longer imports these implementations, receives paths or invokes local file-tool functions. However, arbitrary code with host filesystem access can still modify files, import engine modules, inspect process state or tamper with the gateway. There is no process-user separation, container, filesystem ACL boundary or protection from an operator with engine access. The demo requires the fixed `agents` policy but its trusted owner still selects fixture mode and session settings. General server-assigned enforcement policies are not implemented. In-process `Guard.local` remains cooperative. Do not describe this as tamper-proof enforcement for arbitrary untrusted programs.
- **G7. Session authentication is not agent identity.** Session ownership is the signed-in Clerk subject, derived from a verified JWT, never a supplied owner/identity header. An owner (or anyone holding that owner's valid token) can submit calls under agent IDs in their own session. Cryptographic per-agent delegation and service-account credentials are not implemented. The local SDK is intentionally in-process and not an HTTP authentication bypass.
- **G8. Offline JWT verification has a revocation window.** Sign-out or provider-side revocation does not invalidate an already issued JWT before its expiry. The API verifies signature and expiry on every request; SSE closes at that token's expiry and requires reauthentication. Immediate revocation, centralized introspection and audit records are not implemented. Configure short session-JWT lifetimes and use TLS. Browser state and streams are cleared on account changes; this does not invalidate stolen credentials.
- **G9. Availability and durability are limited.** Private sessions are in-memory and lost on restart; new private sessions are rejected at capacity rather than evicting another owner's traces. Tool fixtures are engine-managed temporary files, removed on session deletion/process exit. Controller evidence is not automatically deleted. Synthetic demos cannot evict private sessions, but public launches and evaluation/execution traffic are not rate-limited and trace histories are not byte-bounded. Do not treat this prototype as production-ready for hostile public traffic. Session-scoped sharing and administrative cross-owner access are intentionally absent. Registered execution requires a session-bound idempotency key: exact retries return the original outcome, concurrent duplicates dispatch once, and changed payloads are refused. Receipts live only as long as the disposable session, not across process restarts; retries with a new key remain new operations. This is not durable exactly-once execution for real payments.

## Reading the evidence

Synthetic results show the controls working end to end on designed scenarios. AI Village results show what the same policy family would have flagged on 1.23M real agent actions; they are counterfactual and say nothing about whether those actions caused harm. Never present AI Village numbers as prevented incidents.
